# Recorded guitar data

This adapter turns the public GuitarSet annotations into canonical TabToPitch note events and bounded coaching contexts. The source is recorded human guitar playing. Questions and candidate descriptors are generated by the application. There are no learner responses, recall labels, or invented practice histories.

The dataset card and measured integrity results live with the downloaded data at the output directory passed to the builder. The source archive is not bundled in the application or service container.

## Reproduce

From the standalone app root, using the pinned npm dependencies:

```sh
python3 research/music-data/acquire.py ../tabtopitch-real-data/guitarset
npx tsx research/music-data/build.ts ../tabtopitch-real-data/guitarset
```

The acquisition script verifies the pinned archive SHA-256 before extracting its 360 JAMS files. It downloads annotations only. The builder checks both the publisher's MD5 and the local SHA-256, verifies the expected corpus size, and fails if the frozen test cohort is incomplete.

`guitarset.ts` owns annotation conversion, source identities, eligibility, and the split. `build.ts` writes:

| File                          | Contents                                                                                                       |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `normalized-recordings.jsonl` | Source pitch observations, exclusion reasons, canonical scores, performer/progression membership.              |
| `split-manifest.json`         | Every recording, source hash, and its frozen split.                                                            |
| `coach-cases.json`            | One bounded phrase per usable recording, with actual generated exercise references and empty learner evidence. |
| `campaign-test-cases.json`    | The 20 test contexts used by the live coach campaign.                                                          |
| `integrity-report.json`       | Eligibility counts and independent answer-contract checks.                                                     |
| `provenance.json`             | Attribution, license, source and output hashes, script revisions, and transformations.                         |

Each source note retains its observation index, fractional MIDI estimate, onset and duration in seconds, inferred fret, and contour statistics. Canonical note IDs include the source file hash, original string index, and observation index. Times use 960 ticks per quarter note at the annotated tempo, preserving observed attacks rather than quantizing them into a score. Source string 0 is low E; canonical string 1 is high E. This mapping is documented by the upstream [visualization interpreter](https://github.com/marl/GuitarSet/blob/master/visualize/interpreter.py).

## What is supported

Pitch-name and exact-pitch-location questions come from the existing application engine. The importer supplies no validated spelling or articulation labels, so interval and triad-role generation is withheld. It is a research adapter for annotation-based questions, not an alphaTab file importer or an audio transcription system.

Frets are inferred from standard tuning and the nearest integer pitch. They are not independent fingering ground truth. Contour agreement is a consistency check against another annotation generated from the same recording, not an independent human label.

Notes are eligible when their pitch is within 35 cents of the nearest semitone, their inferred fret is 0–24, their duration is at least 40 ms, and at least three voiced contour frames support them. The central 80% contour range must be at most 0.5 semitones and its median must agree with the note annotation within 0.2 semitones. These are versioned experimental filters, not established technique detectors. Every rejected note retains all applicable reasons. The three recordings listed in the official errata are excluded without changing their source annotations.
