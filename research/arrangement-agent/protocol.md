# Arrangement agent experiment v1

The decision is whether a bounded model can turn musical requests into the application's arrangement controls reliably enough for an opt-in preview. It does not test teaching effectiveness, playing skill, or preferred musical arrangements.

The frozen test set contains 96 authored requests over 24 musical contexts, each with literal, paraphrase, boundary, and adversarial variants. Two development cases use separate contexts. The contexts cover major/minor, seventh and ninth harmony, alternate tuning, capo, rootless voicings, and explicit melody. These are synthetic fixtures, not GuitarSet observations or learner data. Request variants share context and are not independent musical samples.

Compare the explicit parser and deterministic engine against openai/gpt-oss-20b and openai/gpt-oss-120b. Admit each hosted arm only after catalog discovery and both development cases pass the full tool protocol and semantic checker, including one actual generated proposal. Run two scored trials per admitted model at temperature zero, with at most two completions, 768 output tokens per completion, a 30-second request deadline, no completion retries, and at most 16,384 serialized request bytes. Missing models and qualification failures remain visible.

Each provider request reserves its serialized byte count plus framing as an upper input-token envelope and its maximum completion output. Persist the reservation before sending. Settle to consistent provider usage when available; otherwise retain the reservation. The campaign stops before exceeding 800 calls, 2 million accounted tokens, or the authorized $25 ceiling. Official pricing verified on 2026-10-29 is $0.03 input and $0.13 output per million tokens for 20B, and $0.03/$0.17 for 120B. Source: https://coreweave.com/products/serverless-inference. Dollar figures are estimates from published rates, not invoice reconciliation.

Freeze case membership, expectations, sources, prompt, runtime, scoring, and lockfile hashes before inference. Runtime failures count as false on every criterion and remain in the denominator. Score exact requested controls independently from valid notes, source preservation, melody preservation, boundary handling, and fact references. Candidate generation may find no match for valid requested controls; report usable proposals separately. All factual explanation text comes from checked engine facts. Do not substitute fallback answers for failed model outputs.

Report per-category and per-model outcomes, paired wins/losses against the parser, two-trial agreement, latency, requested/returned model IDs, and usage. Repeated trials estimate stability only. The cloud preview gate requires at least 90% request correctness and zero accepted invalid arrangements or unsupported facts across the complete model arm.

Actual Forge SDK spans capture these public synthetic requests and their actual model/tool outputs. Replay recorded outputs through Weave Evaluation with no new inference; reconcile individual criteria and aggregate counts. W&B Models receives measured campaign summaries. Private user scores, identifying metadata, and practice history are excluded.

Reproduce with `npx tsx research/arrangement-agent/run.ts --prepare`, then `--run`, then `--summarize`. Preparation refuses to overwrite an existing manifest; execution refuses changed sources. Publish using `node --import tsx research/arrangement-agent/publish.mjs` with the selected destination flag. Keep every receipt and failed write; independently read back before any recovery.
